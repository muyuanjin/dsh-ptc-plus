# Rewrite Module Syntax With An AST

## Problem

PTC Plus evaluates each cell as an async function body, where static `import` and `export` declarations are syntactically invalid. The adapter must accept TypeScript type syntax, preserve cell-relative source positions and line counts, classify the rewritten program for replay durability, record every automatic rewrite, and reject malformed or unrecognized module syntax without partially deleting or transforming it. Token-by-token text scanning duplicated parser responsibilities and could accept a recognized prefix while leaving an invalid suffix or erase malformed type-only declarations.

## Decision

[`internal/cell-rewriter.js`](../../internal/cell-rewriter.js) owns module-syntax adaptation. `@babel/parser` parses the original cell with its TypeScript plugin under script semantics while explicitly allowing top-level module declarations, `return`, and `await`; recognizing a module declaration therefore does not impose module strict mode on the surrounding async-function body. Before any edit or module preload record is produced, `@babel/traverse` builds the original Program scope. Its declaration and hoisting rules reject same-scope collisions between value imports and lexical, `var`, function, or other import bindings while retaining block shadowing and the separate TypeScript type namespace. The same scope validates local exports and drives imported-reference rewriting, supplemented by top-level TypeScript declaration names because Babel intentionally excludes the type namespace from runtime scope. The rewriter derives every accepted import, export, type-only declaration, specifier, source value, and edit range from that AST. One batch edit assembler validates non-overlapping ranges, produces generated source, and composes source mappings without rebuilding either artifact per edit. [`internal/cell-analysis.js`](../../internal/cell-analysis.js) then wraps the rewritten cell as an async function body and first parses it with Acorn. Already-valid JavaScript proceeds unchanged; only a cell that Acorn cannot parse is passed through Node's `stripTypeScriptTypes` and parsed again for binding and durability analysis.

Each static import or remote re-export creates an ordered module preload record. A value-bearing record carries its source, import attributes, original position, generated temporary-global identifier, and the default or named exports required by its AST specifiers. The dedicated worker uses Node's synchronous module resolve hook to give REPL imports and static-link adapters one parent at the session cwd, falling back to the worker process cwd when the session has no recorded cwd. Node's ESM resolver therefore owns relative URLs, bare packages, conditional `exports`, URL schemes, import conditions, and platform path conversion; plugin and target-module dependency imports retain their natural parents. Each ephemeral data-URL adapter expresses the required members as static re-exports, so Node completes export linkage before evaluating the target module, then returns the namespace for a value-bearing preload. The worker resolves records before compiling the cell and exposes each namespace under its temporary identifier. One generated lexical prologue after the original directive prologue and before every executable cell statement captures each temporary identifier into a distinct persistent namespace identifier in source order; import declarations are erased at their original ranges, and the temporary globals are removed when the cell settles. Both identities are allocated outside current source identifiers, persistent REPL bindings, reserved program bindings, and every live private namespace. The prologue references the generated host identifier directly, so a lexical `globalThis` binding has ordinary JavaScript semantics and cannot redirect capture. A binding catalog stores only the persistent namespace identity and maps public import aliases to it and the export name; scope-aware rewriting routes unshadowed reads through the namespace, keeps bare, optional, and tagged calls detached from the namespace receiver with the language's comma-reference form, and lowers writes to a deterministic `TypeError`. Private namespace names remain reserved after a public alias is redeclared, so closures from earlier cells cannot be redirected by a later import. The catalog is rebuilt during journal replay. In loose REPL mode an explicit later declaration replaces the alias for future cells, while closures compiled before that declaration retain their namespace read. Destructuring, loop, nested, and delete writes that cannot preserve native evaluation semantics are rejected before execution. Direct `eval` and `WithStatement` are rejected on the original Program while value import aliases are active because generated namespace reads cannot reproduce their dynamic lexical resolution; this validation precedes module preload. Indirect or locally shadowed eval, non-strict `with` without active aliases, and cells containing only type imports retain ordinary JavaScript semantics. Side-effect, default, namespace, named, default-plus-named, and default-plus-namespace forms remain supported. Export modifiers are removed while declarations remain; default exports map the fixed public name `__default` through the same alias lowering to a generated persistent private slot. Later default exports update that slot at their source position independently of variable-redeclaration policy, and the binding catalog adopts the alias definition only after the worker reports the generated post-update commit signal. This keeps `__default` live and read-only while preventing an early return or failed class evaluation from publishing an update that did not execute. Anonymous default function and class lowering emits an explicit statement terminator, while default expressions retain their parsed continuation; remote re-exports become preload-only side-effect modules; local export lists are removed; and declaration-level or specifier-level type-only syntax is erased.

The rewriter normalizes Babel syntax and local-export validation failures as original-cell positions before they cross the module boundary. Executable wrapper parsing retains Acorn's wrapper-relative positions, and only those positions receive the one-line wrapper subtraction during `PTC-C001` rendering. [`internal/cell-analysis.js`](../../internal/cell-analysis.js) then applies return, redeclaration, collision, and durability analysis to the successfully rewritten program. Return control-flow lowering addresses its per-cell worker-global signal through the top-level `this` receiver, which bypasses both lexical `globalThis` shadowing and `with` object-environment resolution; worker startup validates that this receiver is the evaluator's global context, and settlement removes the signal property. Lowered returns emit an explicit statement terminator so a return in a `switch` clause remains valid after replacement. Rewrite provenance remains parallel to the closed journal schema under `meta.dshPtcPlusRewrites` and does not alter replay equality. A successful rewrite remains private audit metadata; only a failed rewrite or missing valid journal may project its description as a bounded recovery context.

## Alternatives considered

**Strip types before any other transformation.** Node's module-mode type stripper rejects the top-level `return` statements that are valid in a PTC cell, so it cannot process ordinary cells.

**Wrap the cell before parsing module declarations.** Wrapping makes top-level returns legal, but static module declarations then appear inside a function and become invalid before they can be identified. It also shifts every AST coordinate and makes module edits depend on wrapper offsets.

**Continue with token-based source surgery.** Recognizing regular-expression literals, nested template expressions, automatic semicolon insertion, comments between modifiers and declarations, and every import/export production recreates a JavaScript and TypeScript lexer. Partial recognition can either reject a valid cell or silently alter a binding, while a complete maintained parser already exposes the required nodes and ranges.

**Extend Acorn with a TypeScript plugin.** This would retain one parser family, but Acorn still cannot represent the PTC cell's combined module-declaration and top-level-return grammar without additional parser customization. It also makes correctness depend on a third-party extension matching both the installed Acorn version and Node's accepted erasable TypeScript syntax.

**Mask returns before parsing.** A correct masker must lex every JavaScript literal and nested expression that may contain `return`, which is the same parser duplication this decision removes. Parser support for `allowReturnOutsideFunction` accepts the cell grammar directly without changing source coordinates.

**Parse the complete cell as a module or use automatic source-type selection.** Both modes impose module strict semantics whenever static module syntax is present, rejecting JavaScript that remains valid in the actual non-strict async-function body. Permissive script parsing separates recognition of module nodes from the execution grammar, while Babel scope traversal retains explicit local-export validation.

**Run the TypeScript stripper for every cell.** Node's TypeScript parser rejects valid non-strict JavaScript such as `with` statements and legacy octal literals even when the cell contains no TypeScript. Letting Acorn accept executable JavaScript first keeps TypeScript erasure conditional and makes the runtime grammar authoritative.

**Destructure the dynamic-import namespace into ordinary REPL variables.** This is compact but copies the current property value instead of preserving an ESM live binding. The REPL convenience layer also makes the generated declaration writable, so reads and assignments both diverge from imported-binding semantics.

**Install import aliases as global accessors.** Getters can expose live values and setters can reject assignment, but they mutate the user-visible global namespace, interact poorly with lexical redeclaration, and make replay depend on worker-global descriptor cleanup. Rewriting only references resolved by the AST keeps the policy in the module adapter and leaves ordinary shadowing to JavaScript scope.

**Emit `await import(...)` inside the REPL cell.** This keeps module loading entirely in generated source, but Node's REPL applies its own top-level-await declaration transform after PTC source mapping. Runtime positions then refer to an unobservable third source, and imports execute at declaration position instead of before the cell body. Worker preloading preserves static-import ordering and leaves one mapped cell source as the diagnostic authority.

**Resolve specifiers with path concatenation or `createRequire.resolve`.** String joining handles relative paths but does not implement URL schemes, package `exports`, ESM conditions, or platform URL conversion. `createRequire.resolve` uses CommonJS resolution conditions and can choose a different package entry from `import`. A scoped Node resolve hook retains the runtime's ESM resolver and changes only the synthetic REPL and adapter parent.

**Load a namespace and inspect its properties.** An own-property check distinguishes an absent export from one whose value is `undefined`, but it runs after the target module has evaluated. Encoding requirements as static re-exports lets Node reject the adapter during linking and prevents target evaluation for that failed preload.

**Compare imported names with generated top-level declarations after rewriting.** This duplicates JavaScript and TypeScript binding rules, loses hoisted declarations nested in statements, and cannot distinguish a valid type-space declaration or block shadow from a runtime collision without rebuilding scope analysis. Validating the original Babel scope keeps the language rule ahead of lowering and preload effects.

## Consequences

Each accepted transformation corresponds to a complete TypeScript AST node, and every automatic type erasure produces provenance without recovering module names from source text. Static modules resolve from the session project in source order before cell compilation; their aliases are initialized before body execution regardless of textual declaration position or an earlier return. A resolution, linkage, or evaluation failure leaves REPL declarations and aliases uncommitted, although a successfully completed earlier preload may already have produced effects. A preload with a missing requested export does not evaluate its target module. Imported reads add one namespace property access; bare, optional, and tagged calls use an indirect reference so the namespace cannot become `this` and nullish optional calls still short-circuit. Malformed module or type syntax and unsupported imported writes fail before execution. The production dependency set includes `@babel/parser` and `@babel/traverse`; Acorn remains the executable-JavaScript and scope-analysis authority downstream. Module resolution uses Node's `registerHooks` primitive available at the engine floor. Node's `stripTypeScriptTypes` is invoked only when the rewritten cell is not already valid JavaScript and remains experimental at the current engine floor, so the compatibility suite must be rerun when the supported Node version changes.
