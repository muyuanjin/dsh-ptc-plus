# Keep REPL Observation Separate From Execution Evidence

## Decision

The REPL console contributes a public `conversation.view` entry alongside Conversation and Trajectory. Its registration follows the browser Client's current session selection and public `agentPreset` projection, appearing only while the plugin and `replViewEnabled` are enabled and the current preset is `ptc` or `code`. `replViewEnabled` defaults to true and does not gate Settings management. The separate `bindingAuthorButtonVisible`, also true by default, hides only the composer authoring shortcut and leaves `/binding` commands available. The existing `userBindingsEnabled` remains the global capability switch. DSH owns selection fallback when an entry disappears. Each contribution consumes its own public slot inputs. REPL registration additionally needs the public sessions selection and projection face; the header and command card use the supplied useProjection hook, and authoring needs the public input hooks and remote command capability. A missing uiSession service name does not block contributions whose public inputs exist. Missing projection inputs suppress dependent session views and leave command cards without draft actions. The view does not access private stores, host DOM, or a second session coordinator.

Session observation and global management appear as consecutive sections of one page, without nested navigation tabs. A compact session table presents neutral binding names, declaration kinds and optional value previews, with name and kind filters over the existing inventory. Empty inventories use a compact full-width state without an empty inspector. Selecting a row shows its recorded definition and value in an adjacent inspector; selection and filtering never request additional observation. The public TypeScript `CodeBlock` highlights and copies only the recorded bounded source, with plain-text fallback when the primitive is absent. Observation time belongs to the section header; truncation and unreadable states accompany each value. The global section and a large Settings-launched public `Modal` reuse one workbench, with separate component lifetimes. Content is ordered as interface declaration, collapsible implementation source, code console and entry configuration. Source is read-only until Edit mounts CodeMirror with TypeScript highlighting, line numbers and document-local history. Editing never executes code. The independent draft console's execution and lifecycle contract belongs to [ADR 0023](0023-global-user-bindings.md). Ordinary global management requires no PTC session. Existing authenticated Connection RPC, revision checks, feature enablement, user execution authority, and persistence-versus-activation semantics remain with their existing owners. Agent authoring retains its session command capability requirement.

The REPL root opts into the same `data-conversation-composer-overlay` layout as the official trajectory view, letting the conversation shell supply a full-height view and disable transcript width handles. While mounted, it registers an empty, session-matched `conversation.composer` chain entry through Cordis-owned effects. The selector declines pending Host interactions and follows existing takeover priority. The public overlay chain keeps the ordinary composer and draft mounted but hidden; view unmount, ineligibility, and provider disposal release the entry and restore the composer. The plugin neither traverses Host DOM nor overrides Host styles.

## Observation Boundary

Only a visible session observation region requests future live-cell previews. The Client combines IntersectionObserver and document visibility, holding a cancellable public Connection RPC `watch` request on `/ptc-plus-repl`. The Host bounds active watchers to 64; abort, connection lifecycle, setting disablement and owner disposal release them. Unexpected request completion clears that request and permits up to three retries after 1, 2 and 4 seconds while visible. Exhaustion leaves no timer; visibility or connection lifecycle changes reset the retry allowance. Cleanup cancels both the active request and pending retry, and stale completions cannot replace a newer request. The handler records interest only and never evaluates code. At live-cell dispatch the runtime checks the current interest and tab setting before generating observation names. Opening the UI cannot refresh historical values, and no visible interest means no optional value inspection. Replay remains outside this path.

Acorn parses successfully executed lowered programs and proves storage for top-level variable declarations: `var` names use own data descriptors from the existing REPL context; `let`/`const` names use lexical storage. Lexical storage takes precedence over same-name global properties, including when uninitialized. Programs containing await are excluded from this proof because Node REPL lowering may change their storage. Failed cells establish no new proof. Unproved names cannot expose unrelated same-name global properties. Bare identifier reads use `vm.runInContext` only for proved lexical names, with a timeout; they never probe unknown global names or invoke root accessors. This path does not use the REPL evaluator, update its last-result binding, invoke imports, or accept expressions from the Client.

`node:util.types.isProxy` rejects proxies, including revoked proxies, before reflection. Own-property descriptors supply shallow descriptions without getters, `toJSON`, custom inspection, prototype traversal, or formatter callbacks. Root functions, symbols, BigInts, proxies and all non-array objects are unreadable. This includes plain objects, typed arrays (including Buffer), boxed strings and module namespaces. No preview enumerates a complete property set. Primitive strings retain their bounded text previews. Arrays provide a finite index range: previews read only the first five own slots, including explicit hole markers. Nested objects remain type markers and accessors remain unreadable markers. The preview omits prototype/internal state. Text is limited to 512 UTF-16 code units, and at most 128 catalog names are inspected. The observation records its start time and is not an atomic heap snapshot. It neither follows later asynchronous mutations nor claims that the model knows these values.

The worker sends normal `done` before optional `observation`. The kernel first performs ordinary execution and journal settlement and detaches execution timers and cancellation listeners. It then waits at most 250 ms for the UI supplement, within the existing cell queue. The worker stops lexical reads after 100 ms and limits each identifier read to 25 ms. Inspection uses fixed array slots and bounded primitive text; it never enumerates arbitrary heap objects. Missing, late, failed, or malformed observations cannot change the settled result or restart a worker. Unsupported inspection degrades to explicit unavailable values. The observer opens no debugging connection and retains only names, never value references.

`dshPtcPlusBindings` metadata version 4 and `ptcPlusRepl` projection state version 4 retain the existing inventory and add optional `{ at, entries }` observation data. Observation candidates first pass through `createReplMemorySnapshot`, sharing the display inventory's name and definition validation, entry limit, and total definition-source budget. Omitted bindings neither consume observation slots nor invalidate previews for visible bindings. Entries carry `{ name, status, text, truncated }`; strict validation and final-catalog filtering prevent foreign names or over-budget text from being published. Source-only metadata version 3 remains readable. A preview is private UI presentation, never a canonical program value, model context, journal entry, recovery proof, or reason to retain hidden state. Existing runtime-generation, seed, restore/discard, and model-visible frontier invalidation governs both the inventory and its attached observation. Cold replay does not collect observations.

Result settlement does not establish worker readiness. Before each cell, the executor sends a private `prepare` message with the cell ID. The worker acknowledges `ready` through the existing private port after preceding synchronous observation and cleanup. Only the matching active cell's first acknowledgement dispatches `run`. The existing compute and wall timers start before `prepare` unless the same worker has an unfinished observation. Observation identity remains separate from the 250 ms presentation deadline; its completion message or a matching readiness acknowledgement starts the deferred timers without restarting an existing budget. A replaced worker cannot inherit the previous worker's observation exemption. Waiting retains the submitted configuration and remains subject to request cancellation, session disposal, and worker failure. Stale, malformed, and duplicate acknowledgements do not dispatch code. Native observation may extend queue waiting after the supplement deadline, but cannot consume the next cell's execution budget. Other blocking work, including previous cells' background callbacks, retains timeout and worker-recovery protection. Readiness uses the existing cell queue and leaves journal records unchanged.

## Alternatives

Ordinary property traversal and serialization can invoke getters, Proxy traps, or custom formatters. General expression evaluation can mutate the session. Inspector-backed previews were rejected because local Inspector sessions produced native Node crashes during Windows worker lifecycle tests, including with explicit disconnection. A separate REPL or cloned state cannot preserve arbitrary closures, modules, handles, and external effects. These are outside the observation contract. The console therefore provides no session code input, object-to-Agent action, or cloned experimental environment.

## Verification

Contract tests exercise lexical and own-data reads, accessors, custom formatters, Proxy traps, revoked proxies, text and structure limits, malformed metadata, missing and late observations, continued binding reuse, and existing recovery invalidation. Readiness tests cover delayed, stale, malformed, and duplicate acknowledgements, cancellation, disposal, worker failure, transport failure, background-callback timeouts, and budget activation after a late observation completes. An isolated process regression compares observation enabled and disabled for a four-million-key plain object in a 128 MiB worker, then verifies later cells retain their 100 ms execution budgets and existing bindings. Public DSH renderer tests exercise current-session registration, setting/provider disposal, observation retry/backoff cleanup, localized observation, shared management, conflict recovery with retained edits, and access through Settings without a session. Playwright checks desktop and narrow layouts and the packed Host integration.
