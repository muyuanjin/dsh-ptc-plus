# Command Goat / DeepSeek V4.1 Flash：2026-10-06 实测

本轮确认了跨 cell 状态复用、同名修订、静态模块语法和主子会话隔离的可用性，也保留了模型错误与评估链路缺陷。**没有证明普通任务的广泛成本收益**：包含子代理的 13 类普通任务 reported token traffic 高出 18.04%；全部 15 类高出 16.64%。少量任务更省、直接工具错误更少，不能抵消这一总体结果。

本报告与[此前同路线实验](command-goat-deepseek-v4.1-flash.md)分开记录。未挑选有利样本覆盖旧记录，也未因结果调整任务或预算。

## 配置与比较范围

使用 Command Goat 的 `deepseek/deepseek-v4.1-flash`，通过实验开始时 npm `latest` 安装未经修改的官方 DSH。实际记录为 DSH `0.2.0-rc.2`、Windows Node `v24.14.0`；版本仅标识本次证据。隔离 DSH home 和工作区，正常 profile、凭据存储及官方安装保持原样。

受测插件运行时来自提交 `c2858ec91dc75e0a637cebb894de4ef00b889da2`，159 份运行时文件的封存 inventory 与实验结束后的字节完全一致。后续评估观察器修复改变证据采集，不改变这批插件运行时。

A/B 固定 15 类任务，每组每类两次，共 60 主会话；正式关联 4 个子代理，两组各 2 个。13 类普通任务为主要分层，`package-name` 和 `static-import-cell` 为能力探针。两组的 provider、model、权限、提示、fixture、Git 初始历史及未提交修改相同，解析后配置唯一处理差异是 `ptc-plus.disabled`。双方都通过相同公开结果 observer 采集规范证据。

fixture 为 `ab-node-project-v1` / `1.0.0`，内容 SHA-256 为 `807580baf64e367bb2dc047c389edf471e13077d54d50ee4b3a143c38f0cebd1`。其 greeting 测试原本失败；检查任务正确报告这一失败才符合要求，不能擅自改成全绿。

任务、预算和 correctness / efficiency / clarity 各 0–3 分的 rubric 在执行前冻结。完成状态与分数分别报告，效率和表达分不能弥补错误答案。普通任务保留全部失败成本；双方均通过质量要求的配对只作次要分层。独立评分者只读取匿名执行材料和最终文件快照，评分与材料 hash 封存后再关联处理组。静态语法及运行行为仍可能提示分组，身份匿名不保证评分者无法猜测处理组。

## 主会话与真实子代理验收

冻结的八项验收 **6/8 通过**，覆盖 8 主会话和 1 真实子代理。成功项观察到跨 cell 连续计算、同名修订、静态 import、编辑派生执行和状态隔离；它们是对应路径的执行证据，不能推出任意任务均成功。

两项失败原样保留：

- 能力探索把 tree/find/inspect 集合一次性返回，11,633 字符超过 8,192 字符内容预算。工具可用不等于模型选择了有界探索。
- 父会话要求返回 `PARENT:42` 标量，模型实际返回包含该值的对象。子代理误用 `code.run({source})`，又在错误报告对象中引用未定义名称；查看接口和保留状态后，正确签名调用成功，返回 BigInt `2n`，四项检查最终均为 true。父会话的“三个 cell、一次 code.run”概括与实际五个 cell、两次尝试不符。恢复成功不抹去错误，也不证明父模型知道子会话中间过程。

验收日志完整处理 236,815 存储字节、738,172 解压字节、294 物理行；严格公开恢复后核对 285 个 own 逻辑事件、36 个逻辑模型步骤、27 对直接调用/结果。两个直接错误分别是预设 syntax 拒绝和子代理 ReferenceError；另有一个被 catch 的 `code.run` 参数错误。日志来源、规范 journal、正式主子身份和已结算流/用量检查通过。

## 停止的首对与评估链路修复

最初 A/B 只执行一对 canary，两组都实际返回正确包名，但基线规范结果缺失，机器判定 incomplete 并停止其余 58 主会话。这两次调用的 **32,348 reported token traffic** 和原判定均保留，不回写为通过。

三处评估实现缺口已在所属入口修正：新增 profile observer 必须使用公开 `insert`，不能更新不存在的条目；真实 Agent 的公开身份来自 `agent.session.id`，而非测试替身虚构的 `sessionId`；子代理规范结果必须留在保留的 artifact 目录，不能随执行 scratch 清理而消失。公开 profile composer、真实 Agent 和官方 Windows Host 的无模型反例检查区分了修复前后，覆盖主子身份、结果来源、policy、嵌套排除、disposer、提示/schema 稳定及清理后留存。

随后重新预登记整个 60 主会话矩阵，任务、rubric、预算和插件运行时字节不变；未选择性重跑不利样本。首对记录为 `2026-10-06T091526-618Z-55431bd3`，完整矩阵记录为 `2026-10-06T100016-332Z-d7e129db`。

## 日志、提示和上下文

完整矩阵逐字节检查 2,444,071 存储字节、8,677,598 解压字节、3,690 物理行；严格恢复后核对 3,626 own 逻辑事件、348 模型步骤、287 对直接调用/结果及 568 次原生分派。检查覆盖 UTF-8 / JSON、字节范围、正式来源、call/result 身份、流与已结算内容、主子 catalog/header/descriptor 关系和完整家族用量。未出现公开恢复、来源闭合或已结算用量矛盾。

直接错误逐项区分：PTC Plus 主会话误用 `fs.createHash`；PTC Plus 子会话未转义报告中的模板字面量；基线一次转义 syntax 错误和三次静态 import 拒绝。前三类是模型代码错误，静态 import 是两组的语言能力差异。没有把预留 greeting 非零退出统称工具错误，也没有把恢复后的成功抹去原错误。未观察到 provider stream failure 或畸形工具 JSON；因此本轮不能评价其修复能力。

每个会话的完整有序 system 文本和工具 schema 均保持字节稳定。PTC Plus 为 **30,830 / 3,363** 字节，基线为 **26,954 / 2,130** 字节，分别增加 **3,876 / 1,233** 字节，共 **5,109** 字节固定前缀成本。64 个 runtime snapshot 的插件状态/catalog 段均为空，未观察到此类重复注入；模型重复读取、重建数据和宽泛探索仍消耗上下文。

缓存读取占 reported 输入 PTC Plus **79.98%**、基线 **78.78%**。这些计数说明本轮有缓存读取，固定前缀说明会话内字节稳定；它们不能证明插件导致缓存提升、全部 provider 缓存键/TTL 稳定或更低账单。实验没有观察强制 compaction、冷恢复或 provider 重试，相关行为不能由本轮推出。

匿名材料在评分前扫描全部文件名、正文和 JSON 键。首次扫描发现两处截断堆栈中的临时工作区 UUID，补齐该身份的匿名投影后重新生成独立材料；原始日志和快照不变，未产生评分或替换样本。修正后的 1,687 份材料、2,946,041 字节通过 728 个已知身份字节形式扫描。源码行为仍可能泄露处理组，盲评结论有此限制。
