<h3 id="cn-v052">宿主适配</h3>

* 目标发行仍是当前官方 DSH，插件继续使用它的公共扩展面（设置卡片座位、会话投影和公共 `Menu`），本版本不要求宿主侧改动
* 升级前写下的会话日志检查点会按新格式重新折叠，旧会话照常恢复，不需要先清空会话或配置

<h3>新增</h3>

* 「能力与上下文 → 提示文本」可以逐句改写插件写给模型的固定提示：每一行标明所属通道、存在条件、字节数和只读原因，只读段落与宿主段落（系统提示与工具说明）只展示、不能改
* 提示文本是一张紧凑表格，点一行展开该行的编辑区；编辑先进草稿，**保存**才生效，**取消**丢弃，保存前可以看到逐条差异及其生效时机（下一次请求、新会话或下次触发）
* 检查点的保留窗口在设置里可调：保留最近单元格数（8–512，默认 8）、保留载荷预算（1 MiB–16 MiB，默认 8 MiB，最坏情况约 32 MB）、单元格簇上限（默认与保留单元格数一致，`0` 表示只由载荷预算约束）
* 计算基线采样、worker 回收、启动探针与宿主执行入口的等待上限，以及连续未测量 cell 的丢弃阈值，都可以按机器情况调整

<h3>稳定性</h3>

* 表面重发布（例如切换工作目录、能力观测、宿主重渲染）不再重建内核：只要 worker 还活着，绑定就在原地保留，视图变化不影响计算状态
* 恢复提示只在真的需要时出现：完整恢复不再发通知，只有确实无法恢复的绑定才被点名（`PTC-R002`），曾被宣布可用之后消失的绑定另有 `PTC-R006` 点名
* 编辑命令是追加语义：被接受的编辑新增一次调用，原有单元格与其绑定保持不变；改写历史是可选的未来能力，默认关闭
* 长会话实测：163 个 run_code 单元格的会话中恢复类诊断数为 0

<h3>修复</h3>

* 会话日志检查点的体积由窗口与预算决定，不再随会话累计写入量无限增长：窗口按条数与字节双重上限把旧结算折成摘要记录，超出预算的单个单元格整簇移除。以每格 20 KB 代码加 20 KB 写入的会话实测，450 格为 0.62 MB、900 格为 0.83 MB
* 被移出检查点的单元格在需要时从会话日志重新折叠，因此仍可编辑和查看；日志无法提供时，编辑会提示「该单元格超出保留窗口，已不可编辑」
* 单个单元格本身就超过载荷预算时，它会连同参数原文一起移出检查点并提示「最新单元格超出保留预算，已从检查点移除」，而不是让检查点无限变大
* 提示文本面板里的原因码与槽位种类按界面语言显示，中文界面不再出现内部代码；只读槽位的说明与按钮样式与设置页其余部分一致
* 选中提示文本的某一行后，编辑区会滚动到可见位置，不再出现「点了行却没看到编辑器」
* REPL 绑定面板在会话投影刷新时保留最后一次确认的清单，不再短暂显示后变成「当前绑定状态尚不可确认」
* 依赖安全：`zod` 解析到 4.6.7（GHSA-mrhx-c7xc-m3w5，high）

<h3>升级</h3>

* 需要 Node.js `^22.19.0 || >=24.0.0`；升级插件后请重启 DSH
* 现有配置不需要迁移：没有显式设置的保留参数使用上述默认值，已有配置里的其它字段照旧生效

```sh
dsh plugin --profile <profile> add dsh-ptc-plus@0.5.2
```

<h3 id="en-v052">Host Compatibility</h3>

* This release targets the current official DSH release and keeps using its public extension surfaces (the settings card seat, the session projection and the public `Menu`); no host-side change is required
* Session-log checkpoints written before this version are refolded in the new format, so existing sessions keep recovering without clearing the session or the configuration

<h3>New Features</h3>

* **Capabilities & context → Prompt text** now lets you rewrite, sentence by sentence, the fixed text the plugin writes for the model. Each row states its channel, when it applies, its byte size and why it is read-only; read-only and host-owned sections (system prompt and tool descriptions) are shown only
* The prompt text surface is a compact table: select a row to expand its editor. Edits stay in a draft, **Save** applies them, **Cancel** discards them, and the pending diff with its effect time (next request, new session or next trigger) is visible before saving
* The checkpoint retention window is configurable: retained recent cells (8–512, default 8), retained payload budget (1 MiB–16 MiB, default 8 MiB, worst case about 32 MB) and the retained cluster limit (defaults to the retained cells; `0` means the payload budget is the only bound)
* The bounds for compute-baseline sampling, worker reclamation, the startup probe and the host execution seam, plus the threshold for consecutive unmeasured cells, can be tuned for the machine

<h3>Stability</h3>

* A surface republish (working-directory change, capability observation, host re-render) no longer rebuilds the kernel: while the worker is alive the bindings stay where they are, and a change of view does not change computation state
* Recovery notices appear only when they are needed: a complete restore is silent, a binding that truly cannot be restored is named (`PTC-R002`), and one that was announced live and later vanished is named separately (`PTC-R006`)
* An accepted edit appends a call: the original cell and its bindings stay unchanged; rewriting history remains a future opt-in, off by default
* Measured on a long session: 163 run_code cells produced zero recovery diagnostics

<h3>Fixes</h3>

* The session-log checkpoint is bounded by the window and the budget instead of growing without limit with what the session writes: a count and byte window folds older settlements into summary records and removes a single cell that exceeds the budget on its own. Measured on sessions writing 20 KB of code plus 20 KB per cell: 0.62 MB at 450 cells and 0.83 MB at 900
* A cell removed from the checkpoint is refolded from the session log when it is needed, so it stays editable and readable; when the log cannot provide it, editing reports "This cell is outside the retention window and can no longer be edited"
* A single cell larger than the payload budget is removed with its argument text and reported as "The newest cell exceeded the retention budget and was removed from the checkpoint", instead of letting the checkpoint grow without bound
* The reason codes and slot kinds in the prompt text surface follow the interface language, so Chinese users no longer see internal identifiers; read-only slot descriptions and buttons match the rest of the settings page
* Selecting a prompt text row scrolls its editor into view, so a selected row always shows the editor it expands
* The REPL binding panel keeps the last confirmed inventory when the session projection refreshes, instead of briefly showing it and then falling back to "Current binding state cannot be confirmed"
* Dependency security: `zod` resolves to 4.6.7 (GHSA-mrhx-c7xc-m3w5, high)

<h3>Upgrade</h3>

* Requires Node.js `^22.19.0 || >=24.0.0`; restart DSH after upgrading the plugin
* No configuration migration is needed: retention fields that are not set use the defaults above, and other configured fields keep their values

```sh
dsh plugin --profile <profile> add dsh-ptc-plus@0.5.2
```
