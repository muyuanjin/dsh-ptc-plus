<h3 id="cn-v054">宿主适配</h3>

* 目标仍是当前官方 DSH 发行：插件继续使用它的公共扩展面（设置卡片座位、会话投影、能力探测与公共 `Menu`），本版本不要求宿主侧改动，也不按宿主版本分支
* 支持哪些宿主仍由通道表达，而不是由版本号判定：`latest` 与 `next` 是阻塞通道，`alpha` 线只报告结果

<h3>新增</h3>

* 会话能力面板直接列出全局绑定条目，并在面板里控制这个会话用不用它：每行只有三种读法，「本会话使用」「本会话不使用」「全局已关闭：该条目在全局停用」，前两种可点击切换
* 点击提交的就是人类输入的同一条 `/binding use|skip <id>` 命令，面板不新增写通道；结果按同一份会话能力目录回读，因此面板显示的取用状态与命令本身一致；同一行提交期间整组控件一起禁用，应用进行期间绑定控件也禁用，已提交的命令不会被另一次操作打断

<h3>修复</h3>

* 会话没有活动运行时，能力面板不再显示「能力清单读取失败：… select an active PTC session」：它用一句话说明本会话的能力尚未清点，清单留空而不是留一条错误
* 绑定组产不出来时不再画成空组：全局绑定关闭时说明这一点，条目或本会话的取用记录读不出时说明状态尚不可知；可读但没有任何条目时显示「尚无全局条目」，与两种缺席原因分开
* 本会话没有列出 `/binding` 命令时，绑定条目仍照常列出，控件禁用并在组内注明原因，而不是看起来能点却没有反应
* 面板里的关闭按钮在命令提交期间禁用且关闭路径本身拒绝关闭，`Escape` 与背景点击都不会中止已经提交的应用或绑定决定；设置或命令可用性变化同样不会中止它们

<h3>升级</h3>

* 需要 Node.js `^22.19.0 || >=24.0.0`；升级插件后请重启 DSH
* 不需要配置迁移：本版本不改配置字段；旧会话日志不需要清理或重写

```sh
dsh plugin --profile <profile> add dsh-ptc-plus@0.5.4
```

<h3 id="en-v054">Host Compatibility</h3>

* It still targets the current official DSH release and keeps using its public extension surfaces (the settings card seat, the session projection, capability probing and the public `Menu`); no host-side change is required, and no behaviour branches on a host version
* Which hosts are supported is still expressed as channels rather than decided by a version number: `latest` and `next` are the blocking channels, and the `alpha` line is reported on without blocking a release

<h3>New Features</h3>

* The session capability panel now lists the global binding entries and controls, for this session, whether it uses one: every row says one of three things — used in this session, not used in this session, or off globally because the entry is disabled — and the first two can be toggled
* Clicking submits the same `/binding use|skip <id>` command a human types; the panel adds no write channel, and it reads the result back from the same session capability catalog, so the state it shows is the command's own state. While one row submits, the whole group's controls are disabled, and the binding controls are disabled while an apply runs, so neither path interrupts a command already submitted

<h3>Fixes</h3>

* A session with no live runtime no longer makes the capability panel show a capability-list failure ("select an active PTC session"): the panel says in one sentence that this session's capabilities have not been observed, and leaves the inventory empty instead of leaving an error
* A binding group that cannot be produced is no longer drawn as an empty group: the panel says whether global bindings are off or whether the entries or this session's adoption record cannot be read, and a readable supply with no entries shows its own empty sentence instead of either absence reason
* When `/binding` is not listed in this session, the binding entries are still listed, their controls are disabled, and the reason is stated in the group instead of leaving controls that look usable but do nothing
* The panel's close button is disabled while a command is submitted and the close path itself refuses to close, so `Escape` and a backdrop press cannot abort an apply or a binding decision that was already submitted; a change in settings or command availability does not abort them either

<h3>Upgrade</h3>

* Requires Node.js `^22.19.0 || >=24.0.0`; restart DSH after upgrading the plugin
* No configuration migration is needed: no configuration field changes in this version, and existing session logs need no cleanup or rewrite

```sh
dsh plugin --profile <profile> add dsh-ptc-plus@0.5.4
```
