<h3 id="cn-v054">宿主适配</h3>

* 目标仍是当前官方 DSH 发行：插件继续使用它的公共扩展面（设置卡片座位、会话投影、能力探测与公共 `Menu`），本版本不要求宿主侧改动，也不按宿主版本分支；`engines.dsh` 声明 `>=0.2.1-0 <0.2.3`
* 会话的能力决定与绑定取用改为写进会话日志本身，不再占用对话消息：重载或重启后恢复会话时，面板读到的仍是当时那次决定，模型也不会因此多收到一条消息
* 支持哪些宿主仍由通道表达，而不是由版本号判定：`latest` 与 `next` 是阻塞通道，`alpha` 线只报告结果

<h3>新增</h3>

* 会话能力面板按「宿主提供了什么、这个会话记录了哪些决定、证据落在哪一层」重排：每行分列陈述对象、类型、来源、已保存的启用与披露、本会话的启用与披露，以及这一行的回执；点击列头可按该列排序
* 会话里直接列出全局绑定条目，并在面板里控制这个会话用不用它：每行按本会话的采纳记录读作「使用」「不使用」或「记录损坏」，点这一格就写下这个会话的取用；全局已停用的条目不出现在清单里。点击提交的就是人类输入的同一条 `/binding use|skip <id>` 命令，面板不新增写通道，结果按同一份会话能力目录回读
* 面板同时出现在会话入口与设置页：设置页编辑保存的规则，会话入口只写本会话的记录，两个入口各自固定自己的地址，不互相代替
* 支持一次选择多行、批量写下同一个决定，每行仍然各写一条记录，回执列逐行说明这次决定落在哪一层

<h3>修复</h3>

* 本会话关闭过的能力不再出现在任何模型可见处：`tools:sdk` 声明块、程序里真实的 `tools` 成员、`capabilities.*` 的探索结果，以及能力方案与说明段，都与这个会话真正可调的成员保持一致，关闭的能力不会只剩声明还在
* 已保存的开关单独成列陈述，不再与本会话的记录混读：一列只回答「保存了什么」，另一列只回答「这个会话记录了什么」
* 设置页的能力表格恢复滚轮滚动：鼠标停在表格上时页面照常滚动；名称与来源单行省略，完整文字保留为悬浮提示，长名字不再把整行撑高
* 本版本写入的能力决定不会再让会话在重载时读不出来；旧版本留下的这类日志不再由新版写入
* 没有活动运行时的会话不再被读成「读不出来」：面板读它日志里最后一版方案，列出的行与有运行时时一致；真的读不出来时，错误与重试就写在行旁
* 绑定组永远在：读失败在行旁报出并可重试；可读但没有任何条目时它就是一张空表，不另配一句解释

<h3>升级</h3>

* 需要 Node.js `^22.19.0 || >=24.0.0`；升级插件后请重启 DSH
* 不需要配置迁移：本版本不改配置字段；已有会话日志不需要清理或重写

```sh
dsh plugin --profile <profile> add dsh-ptc-plus@0.5.4
```

<h3 id="en-v054">Host Compatibility</h3>

* It still targets the current official DSH release and keeps using its public extension surfaces (the settings card seat, the session projection, capability probing and the public `Menu`); no host-side change is required, and no behaviour branches on a host version. `engines.dsh` declares `>=0.2.1-0 <0.2.3`
* A session's capability decisions and binding adoption are now written into the session log itself instead of taking up conversation messages: when a session is reloaded or resumed after a restart, the panel still reads the decision that was made, and the model receives no extra message for it
* Which hosts are supported is still expressed as channels rather than decided by a version number: `latest` and `next` are the blocking channels, and the `alpha` line is reported on without blocking a release

<h3>New Features</h3>

* The session capability panel is organised around what this host supplies, which decisions this session recorded, and which layer the evidence belongs to: each row states its object, type, source, the saved availability and disclosure, this session's availability and disclosure, and that row's receipt; a column header sorts by its own column
* The panel lists the global binding entries and controls, for this session, whether it uses one: every row reads as used in this session, not used in this session, or a damaged record, and its cell writes this session's adoption when it is clicked; an entry disabled globally is not listed at all. Clicking submits the same `/binding use|skip <id>` command a human types, the panel adds no write channel, and it reads the result back from the same session capability catalog
* The panel appears at both entrances: the settings page edits saved rules, the session entrance only writes this session's record, and each entrance fixes its own address instead of standing in for the other
* Several rows can be selected and given the same decision at once, each still writing its own record, and the receipt column says per row which layer the decision reached

<h3>Fixes</h3>

* A capability this session closed no longer appears anywhere the model can see: the `tools:sdk` declaration block, the real `tools` members of a program, what `capabilities.*` can explore, and the capability plans and guidance sections all agree with the members this session can actually call, so a closed capability is never left declared on its own
* The saved switch is stated in its own column instead of being read together with this session's record: one column answers only "what is saved", the other only "what this session recorded"
* The settings capability table scrolls with the wheel again: the page scrolls while the pointer is over the table, the name and source clip to one line with the full text kept as a tooltip, and a long name no longer makes its whole row taller
* A capability decision written by this version no longer makes a session unreadable when it is reloaded, and the logs older releases left behind are no longer written by this one
* A session with no live runtime is no longer read as unreadable: the panel reads the last plan its log carries and lists the same rows a live session lists, and a read that really fails states the error and its retry beside the rows
* The binding group is always present: a failed read is reported beside the rows with its retry, and a readable group with no entries is an empty table rather than a sentence explaining it

<h3>Upgrade</h3>

* Requires Node.js `^22.19.0 || >=24.0.0`; restart DSH after upgrading the plugin
* No configuration migration is needed: no configuration field changes in this version, and existing session logs need no cleanup or rewrite

```sh
dsh plugin --profile <profile> add dsh-ptc-plus@0.5.4
```
