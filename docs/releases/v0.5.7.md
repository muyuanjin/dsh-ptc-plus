<h3 id="cn-v057">宿主适配</h3>

* 适配 DSH `0.2.2-rc.2` 的官方 Cordis 开发 Skill；启用 `cordisToolsEnabled` 后加载 `dsh-doc`，同时保留旧版宿主的兼容入口
* DSH 安装准入范围保持 `>=0.2.1-0 <0.2.3`；运行时接口继续按宿主提供的公共能力选择

<h3>修复</h3>

* 宿主显式重置程序环境后，会话变量、命名 checkpoint 和可编辑目标会被清除，重启或 fork 后也不会恢复；普通 Agent 释放仍保留可验证的会话恢复
* 历史重置记录缺失或包含不支持的版本时，只收缩一次无法验证的状态；后续已确认的新计算可跨冷恢复和 fork 保留，不重复执行历史外部操作
* 包含多次重置的会话日志可正常迁移，并保留重置后计算的恢复关系
* Windows 开发启动器使用实际 Windows Node.js 检查监听端口，自动替换被占用或拒绝访问的缓存端口；手动指定的端口保持原值，探测失败时保留原缓存并停止启动
* “绑定更新语义”设置直接显示当前策略，可选择“允许重声明和覆盖”（`stateful`）或“启用名称保护”（`protected`）；已有配置值保持不变

<h3>升级</h3>

* Node.js 需同时满足插件的 `^22.19.0 || >=24.0.0` 与所选 DSH 的要求；DSH `0.2.2-rc.2` 要求 Node.js `>=24.9.0`
* 无需迁移插件配置；升级后重启 DSH。插件升级不会自动改写历史会话日志

```sh
dsh plugin --profile <profile> add dsh-ptc-plus@0.5.7
```

<h3 id="en-v057">Host Compatibility</h3>

* Adapts to the official Cordis development Skill in DSH `0.2.2-rc.2`: enabling `cordisToolsEnabled` loads `dsh-doc`, while retaining the compatibility entry for older Hosts
* The DSH admission range remains `>=0.2.1-0 <0.2.3`; runtime interfaces continue to follow the Host's public capabilities

<h3>Fixes</h3>

* An explicit Host environment reset clears session variables, named checkpoints and edit targets across restart and fork; ordinary Agent disposal still preserves verifiable session recovery
* Missing or unsupported versions in historical reset records contract unproved state once; subsequently confirmed computation survives cold recovery and fork without repeating historical external operations
* Session logs containing multiple resets migrate successfully while preserving recovery relationships for post-reset computation
* The Windows development launcher probes listening ports with the actual Windows Node.js runtime and replaces occupied or denied cached ports; explicit ports remain unchanged, and failed probes preserve the cache and stop startup
* The “Binding update semantics” setting displays the selected policy by name: “Allow redeclarations and overrides” (`stateful`) or “Protect names” (`protected`); existing configuration values remain unchanged

<h3>Upgrade</h3>

* Node.js must satisfy both the plugin's `^22.19.0 || >=24.0.0` range and the selected DSH requirements; DSH `0.2.2-rc.2` requires Node.js `>=24.9.0`
* No plugin configuration migration is needed; restart DSH after upgrading. A plugin upgrade does not rewrite historical session logs automatically

```sh
dsh plugin --profile <profile> add dsh-ptc-plus@0.5.7
```
